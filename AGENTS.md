# Авто || ПараLLель — инструкции для работы в репозитории

## Задача проекта

Сайт российского агентства по подбору автомобилей из Китая, Кореи и Европы. Главная задача покупателя: найти автомобиль, сравнить варианты, понять известные расходы и подготовить предметное обращение. Упрощай этот путь; сохраняй единый каталог и компактную админку.

Продолжай работу в пределах запроса пользователя. Используй уже согласованные решения; не запрашивай повторное подтверждение обычных обратимых правок. Этот файл не меняет разрешения инструментов и не отменяет инструкции пользователя.

## Архитектура и исходники

- Стек: HTML, CSS, JavaScript/ES modules; Node.js >=22.13, встроенная SQLite для локальной админки. Не переходи на React/Next.js без конкретной необходимости и согласованной задачи миграции.
- `catalog-section.html` — исходник единого каталога. `scripts/generate-buyer-section.mjs` собирает многостраничный сайт: `index.html`, `catalog/index.html`, `import/index.html`, `budget/index.html`, `contacts/index.html`. Контент остальных страниц — `pages/*.html`; общая оболочка/меню — генератор и `assets/site-pages.js`/`.css`. Меняй исходники и запускай сборку; прямые правки сгенерированных HTML будут затёрты. На вложенных страницах `<base href="../">` сохраняет пути к ресурсам и карточкам внутри проекта GitHub Pages.
- `order.js`, `order-engine.mjs`, `assets/buyer-*.mjs` — актуальные фильтры, подбор, сравнение и сохранения. `app.js`, `guide.js`, `suppliers.js` содержат также прежние сценарии: проверяй зависимости перед удалением; не создавай второй конкурирующий каталог.
- `cars/vehicle/index.html`, `assets/vehicle-page.js`, `assets/vehicle-page.css` — общая страница объявления. Статические страницы агентских объявлений/моделей генерируются отдельно.
- `assets/premium.css` уточняет существующую главную страницу поверх старых стилей. При изменениях учитывай каскад и мобильные правила.
- `data/vehicles/` — структурированные агентские записи; `data/import/` — сохранённые данные поставщиков. `order-catalog.json` и `catalog-data.js` генерируются сборкой; исправляй первичный источник, а не только результат генерации.
- `server/`, `lib/`, `admin/` — сервер, опубликованные правки, админка и очереди. Действительные изменения администратора могут отличаться от статического каталога.
- `dist/` — результат сборки, не источник. Статический GitHub Pages и локальный сервер админки имеют разные возможности.

## Данные и честные обещания

- Не выдумывай автомобили, фотографии, цены, отзывы, статистику, реквизиты, гарантии, адреса или доступность поставки. Демонстрационные данные явно называй демо.
- У объявления сохраняй постоянный ID, источник, исходную валюту, дату и статус. Историческая публикация и сохранённое объявление не подтверждают наличие сегодня.
- Не называй загрузку всех четырёх площадок полной без проверяемого отчёта об охвате. Справочник моделей не является предложениями поставщиков.
- Показывай автомобили с фотографиями; при недоступности всех фото сообщай об этом и не подменяй их вымышленной фотографией.
- Не превращай неизвестные год, пробег или двигатель в ноль. Пробег `0` — допустимое известное значение.
- Не сравнивай разные валюты напрямую. Для рублёвой оценки нужны проверенные курсы, тарифы, состав расходов и даты актуальности. Условные пошлины/утильсбор не выдавай за действительные.
- Бюджет на весь заказ (`budgetWish`) — пожелание для расчёта, а не фильтр зарубежной цены и не подтверждение попадания автомобиля в бюджет.
- До подключения действующей интеграции формы лишь готовят/копируют текст. Не показывай «заявка отправлена», CRM-статус или уведомления, которых нет. Сохранённые поиски сейчас локальные, без серверных подписок.
- Подтверждённый Telegram: https://t.me/autollparallel. Остальные контактные сведения используй только из подтверждённых данных проекта/пользователя.

## Визуальная система и UX

- Сохраняй фирменные цвета: navy `#0D2948`, orange `#FF882B`, paper `#F5F5F2`, graphite `#171A1F`. Основной шрифт — локальный Manrope с кириллицей, `assets/fonts/`.
- Характер интерфейса: крупные настоящие фотографии, читаемые названия, спокойная типографика и ясная иерархия. Согласуй общие кнопки, отступы и состояния между каталогом, карточкой и админкой; не добавляй декоративные секции ради заполнения страницы.
- Для улучшений интерфейса используй подходящие доступные дизайнерские навыки, сохраняя текущий бренд. Не устанавливай весь список инструментов только потому, что он упомянут в рекомендации.
- Сначала используй простые CSS/JS-возможности. GSAP, Lenis, Spline и другие зависимости добавляй под конкретную оправданную задачу, с проверкой производительности и лицензии. Не перехватывай обычную прокрутку без необходимости.
- На мобильных проверяй поиск, фильтры, сравнение, галерею, форму и закреплённые действия. Предусматривай перенос длинных названий, safe-area и отсутствие перекрытия полей.
- Сохраняй семантические ссылки/кнопки, подписи полей, видимый клавиатурный фокус, его возврат после диалогов, цели нажатия от 44px и `prefers-reduced-motion`.
- При возврате из объявления сохраняй фильтры, бюджет и общую подборку, включая back/forward cache. Не удаляй сохранённый выбор при настройке поиска.
- Береги загрузку: локальные шрифты, размеры изображений, lazy loading второстепенных фото, отсутствие тяжёлого 3D без необходимости. Прямая страница объявления пока может загружать весь каталог (~6 МБ); не называй это оптимизированным запросом одной записи.

## Запуск и проверка

Из корня репозитория:

```sh
npm run dev          # сайт: http://127.0.0.1:4173
npm run admin        # админка: http://127.0.0.1:4181/admin/
npm run build        # синтаксис, данные, бизнес-логика, ресурсы, ID, ссылки, dist/
npm run test:admin   # сервер/авторизация/импорт/фото: при изменении этих областей
```

- После изменений кода/данных запускай `npm run build` и `git diff --check`. Для документации достаточно проверки текста, путей и diff; полная сборка без изменений приложения не обязательна.
- Проверяй затронутую бизнес-логику: валюты, неизвестные значения, нулевой пробег, ограничения поиска, сохранения и маршруты GitHub Pages. Не добавляй тесты, просто повторяющие реализацию.
- Интерфейс проверяй в настоящем браузере на desktop и мобильном размере через разрешённые инструменты: визуальная композиция, клавиатура, галерея, фильтры, сохранения, возврат и копирование запроса. Playwright/скриншоты — инструменты проверки, а не замена фактического запуска.
- Если инструмент отказал по политике безопасности, не обходи отказ через другой браузерный драйвер, CDP или скрытый запуск. Продолжай разрешённую работу; точно укажи, какие проверки не выполнены. Один прежний отказ не доказывает постоянную блокировку.
- Не объявляй визуальную проверку, мобильные тесты, показатели Lighthouse/PageSpeed или отсутствие ошибок без полученного результата. Статический детектор и успешная сборка не доказывают правильность отображения.

## Сохранность и размещение

- Сохраняй пользовательские изменения. Не выполняй разрушительный сброс истории, перезапись данных или очистку папок ради удобства сборки.
- Существующий исходный бэкап: тег `backup-before-unified-selection-20261021`, коммит `87f8d20`; инструкция `docs/ROLLBACK.md`. Тег не передвигай. Перед крупными изменениями проверь состояние Git и доступную точку восстановления.
- `.admin-data/`, `vehicle-library/`, `.local-source/` исключены из Git: это рабочая база/загрузки, оригиналы и среда обработки. Git-бэкап не является бэкапом этих данных.
- Оригиналы фото сохраняй, производные связывай с автомобилем и исходником. Не восстанавливай выдуманные повреждения, комплектацию или другие скрытые детали автомобиля.
- Не коммить пароли, сессии, токены, приватные выгрузки или модели обработки. Не переинициализируй действующую учётную запись администратора ради тестов; серверные тесты используй с временными данными.
- Локальная правка, Git-коммит, отправка на GitHub и публикация — разные операции. Выполняй публикацию в рамках явного запроса или уже данного разрешения; в отчёте точно называй выполненный этап. GitHub Pages не запускает сервер админки и ночные задачи.
