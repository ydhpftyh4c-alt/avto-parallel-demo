# Автоматическая обработка фотографий

Управление находится в **Настройки → Автообработка фотографий** локальной админки. Отдельного раздела в меню нет. Один переключатель включает ночную обработку и автоматическую замену подходящих снимков; выключение приостанавливает следующие кадры. Кнопка **Обработать сейчас** добавляет до 100 новых кадров в фоновую очередь. Ручная проверка доступна в свёрнутом блоке **Проверить исключения**.

## Что уже включено на этом компьютере

- Ночное окно: 02:00–06:00 по Москве, пока ПК и сервер включены и компьютер не спит.
- Бюджет: до **2 000 фото за ночь**. Это лимит, а не обещание обработать столько при любой сети.
- Запущена дополнительная первая партия из 30 кадров. Ранее принятые снимки не перезаписываются.
- Типовой центральный знак LOTTE `wm_224` автоматически заменяется только при уверенном распознавании, допустимом размере маски, совпадении модели и проверке неизменности пикселей вне маски.
- Нераспознанные и сомнительные изображения сохраняются без замены; возможные варианты доступны в исключениях. Произвольные логотипы дилеров и все надписи на стенах автоматически не распознаются.
- Оригинал и история карточки сохраняются. Автоматическую замену можно вернуть через историю объявления.

Восстановление скрытых знаком деталей — предположение модели. Проверка пикселей вне маски не подтверждает точность восстановленного участка внутри неё.

## Реальный замер RTX 2060 SUPER 8 ГБ

На восьми ранее скачанных фотографиях 20.10.2026 с последовательным OCR + LaMa + сохранением PNG:

| Показатель | Результат |
|---|---:|
| Вся партия, включая первый запуск | 17,36 с |
| Первый кадр | 4,88 с |
| Медиана последующих кадров | 1,375 с |
| Темп этой локальной партии | около 1 658 фото/час |
| Пик резервирования памяти PyTorch | 1 772 МиБ |

Загрузка из интернета в замер не входит. Для ночного лимита используется 30% измеренного локального темпа × длина ночного окна, с округлением до сотни: примерно 2 000 фото на четыре часа. Остальное время оставлено на загрузку, вариацию изображений и другие задания. По фактической сети результат может быть ниже. Подробный отчёт: `.local-source/retouch-benchmark/report.json`; повторный замер: `node scripts/benchmark-retouch.mjs`.

Модель и OCR загружаются один раз на последовательную очередь. Один GPU-обработчик работает без параллельных тяжёлых инференсов, после 60 секунд простоя процесс завершается и освобождает память. Рабочая сторона ограничена 1024 px, производная сохраняется в исходном размере. Загрузчики и обработчик фотографий имеют независимые очереди: ретушь не ждёт полного скачивания всего каталога. У каждого изображения есть тайм-аут 5 минут.

## Сохранность данных

Исходники не перезаписываются. Хранятся оригинал, маска, результат, SHA-256 исходника и модели, версия, найденные слова, время и статус. PNG собирается из исходных RGB-пикселей и восстановленного участка; все пиксели вне маски проверяются на равенство. EXIF-ориентация учитывается. Скрытые детали и исходное JPEG-сжатие не восстанавливаются.

Повтор одинакового содержимого с той же маской, версией и моделью использует кеш. Ранее отклонённый вариант не применяется автоматически. Автозамена сохраняет последние правки карточки и проверяет её версию и наличие исходной фотографии. Прерванную обработку можно повторить в исключениях. Неоконченный ночной пакет ждёт следующего окна, новый пакет не раздувает остаток.

- `.admin-data/admin.sqlite`, `photo_tasks`: очередь и метаданные.
- `.admin-data/retouch/<UUID>/input`, `mask.png`, `result.png`, `task.json`: приватные файлы.
- `.admin-data/uploads/<UUID>.png`: принятые фотографии карточек.
- `.local-source/retouch-models/big-lama.pt`: модель; `.local-source/retouch-env`: окружение.

Изображения обработки доступны только через авторизованные API. SQLite-бэкап **не включает файлы**: для полного восстановления копируйте также `.admin-data/retouch`, `.admin-data/uploads` и оригинальную библиотеку.

На сайте сервера 4181 замены видны сразу. Локальный предпросмотр 4173 получает живой каталог и принятые фото от сервера 4181, пока он работает. GitHub Pages обновляется через обычный экспорт, сборку и отдельную публикацию.

## Установка и перенос

На текущем компьютере всё установлено. Для другого Windows-компьютера с Python 3.12 из корня проекта:

```powershell
powershell -File scripts/Setup-PhotoProcessing.ps1
# Без NVIDIA:
powershell -File scripts/Setup-PhotoProcessing.ps1 -CpuOnly
```

Отдельное окружение: PyTorch 2.6.0 CUDA 12.6, NumPy 1.26.4, Pillow 11.3.0, OpenCV 4.11.0.86, RapidOCR ONNX 1.4.4. CUDA-сборка PyTorch — около 2,5 ГБ, модель LaMa — около 206 МБ. При переносе на Linux создайте аналогичный venv вручную; Windows-скрипт там не запускается. Можно переопределить `RETOUCH_PYTHON` и `RETOUCH_MODEL`.

Модель: https://github.com/enesmsahin/simple-lama-inpainting/releases/tag/v0.1.0

SHA-256 `big-lama.pt`: `7ba7aa7ac37a4d41fdbbeba3a2af7ead18058552997e3a3cd1a3b2210c9e6b4c`.

Схема маски и инференса основана на примере [simple-lama-inpainting](https://github.com/enesmsahin/simple-lama-inpainting), Apache-2.0. Исходный LaMa: https://github.com/advimman/lama. OCR: https://github.com/RapidAI/RapidOCR. Зависимости и веса имеют собственные лицензии.

После переноса повторите замер: бюджет зависит от компьютера. Без отчёта автообработка сама не включается. `PHOTO_INITIAL_BATCH=30` при запуске сервера однократно добавляет до 30 кадров; значение удаляется из окружения процесса после старта.

Проверки:

```powershell
node --test server/admin.test.mjs server/jobs.test.mjs server/import.test.mjs server/photos.test.mjs
.local-source/retouch-env/Scripts/python.exe server/retouch_test.py
node scripts/build.mjs
```
